# Обновление ТАСС — 0.3.0

Обновление касается ТАСС. Логика e-disclosure, подготовки браузерной сессии,
MOEX, основной `compose.yaml`, `core.py` и фронт сохранены.

## Что исправлено

В присланном `tass.json` находятся реальные новостные тексты, но в поле `text`
попали навигация, повтор заголовка, авторство, время на странице, подписи к фото,
ссылки «Читайте также» и теги. Новый адаптер выделяет тело статьи:

- Сначала читает `articleBody` из JSON-LD, затем семантический блок статьи.
- Собирает все абзацы и подзаголовки, сохраняет цитаты, числа и текст inline-ссылок.
- Удаляет служебные блоки до преобразования HTML в текст.
- Очищает известные примеси в старом плоском представлении; не переписывает
  факты, не использует LLM и не сокращает содержательные абзацы.
- Берёт дату публикации из RSS, публикационных метаданных или JSON-состояния
  именно текущей статьи. `dateModified`, дата события в первом абзаце и одинокое
  `HH:MM` не подменяют время публикации.
- Повторяет чтение DOM при редиректе/смене страницы. После загрузки ждёт два
  согласованных снимка текста, заголовка и доступной даты.
- После первого HTTP-отказа на статье выбирает Chromium для оставшихся статей
  этого запуска, без повторения одинаковых неудачных HTTP-запросов.

В `run_report.json` для ТАСС добавлены:

```json
{
  "invalid_reasons": {"missing_published_at": 2},
  "invalid_records": [
    {"url": "https://tass.ru/ekonomika/1", "reasons": ["missing_published_at"]}
  ]
}
```

Это пример формата, не реальные результаты. Возможные причины:
`missing_title`, `missing_published_at`, `missing_or_short_body`.
В списке сохраняются первые 200 проблемных URL; счётчики учитывают все пропуски.
Сетевые ошибки по-прежнему записываются отдельно в `errors`.

## Установка

Скопируйте **содержимое `update/`** из архива в корень своего репозитория
`Alfa_bank_hack`, объедините папки и замените совпадающие файлы.
Не заменяйте всю рабочую ветку полным проектом из `Alfa_bank_hack-main/`.
Папки с данными и основной конфигурации Compose в `update/` нет.

Затем из `alfa-context`:

```bash
docker compose build parser
docker compose run --rm parser --sources tass --limit 5 --max-pages 3
```

e-disclosure этой командой не вызывается. Выдача остаётся в `data/news/tass.json`
и `data/news/news.json`. Окно 48 часов, лимит 200, ID и JSON-схема записей прежние.

Уже выгруженные ID повторно не выдаются: поэтому прежние пять статей не обязаны
появиться после обновления. Для повторяемой проверки в отдельной папке, сохранив
основное состояние и переиспользовав сессию:

```bash
docker compose run --rm parser --sources tass --limit 5 --max-pages 3 --output /data/tass-check --browser-state /data/.browser-state.json
```

Результаты этого прогона будут в `data/news/tass-check/`. Основной `state.json`
останется прежним. Все даты по-прежнему проверяются относительно начала запуска.

Для сбора обоих действующих источников:

```bash
docker compose run --rm parser --sources moex tass
```

## Если ТАСС запросил проверку посетителя

Существующий механизм подготовки сессии можно вызвать **только для ТАСС**:

```bash
docker compose -f compose.session.yaml run --rm --service-ports parser-session --sources tass --output /data/.browser-state.json
```

Откройте `http://localhost:6080/vnc.html?autoconnect=true&resize=scale`, дождитесь
настоящей ленты ТАСС, при необходимости пройдите проверку вручную, затем нажмите
Enter в терминале. После сохранения сессии повторите обычный сбор.
e-disclosure при такой подготовке не открывается и не мешает сохранить сессию.

После обновления для этой команды предварительно пересоберите образ, если
профиль сессии уже использовался:

```bash
docker compose -f compose.session.yaml build parser-session
```

## Проверка результата

```bash
docker compose --profile test run --build --rm parser-test
docker compose run --rm --entrypoint python parser -m news_parser.check /data
```

Для отдельной проверочной папки:

```bash
docker compose run --rm --entrypoint python parser -m news_parser.check /data/tass-check
```

В архиве также есть `tass.cleaned.json`: очищенная копия пяти присланных записей.
ID, URL, заголовки, даты и категории в ней не изменены. Это образец очистки
пользовательского файла, а не новая сетевая выгрузка. Не заменяйте им свежую
порцию автоматически, особенно если её окно уже другое.

## Границы проверки

Регрессионные тесты используют все пять присланных записей. Отдельные тесты
проверяют сохранение фактических абзацев, цитат, временных отметок внутри текста,
дату конкретной статьи, исключение времени обновления, диагностику пропусков,
повтор чтения при навигации и настоящий Chromium с тестовым редиректом.

При подготовке в этой среде RSS ТАСС загрузился. Новую живую выгрузку полных
текстов подтвердить не удалось: страницы отвечали защитой, а Chromium столкнулся
с недоверенным сертификатом сетевого посредника среды. Проверка TLS не отключена.
Корректность очистки присланных данных и тестовых HTML проверена отдельно от
доступности сайта. Docker здесь отсутствует, сборка образа локально не выполнялась.
