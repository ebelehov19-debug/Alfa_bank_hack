# Альфа Контекст — локальная CPU-модель

Qwen2.5-1.5B-Instruct Q4_K_M через llama.cpp b11856.
Python 3.12+, стандартная библиотека, Ubuntu 24.04 / WSL2 x86_64.
Ollama, Docker, GPU и pip-пакеты не нужны.

## Быстрый запуск

Из WSL:

~~~bash
cd ~/dev/mai/alfa-bank-hackaton/alfa-context
# Один раз (уже выполнено в текущем рабочем каталоге):
bash setup-local.sh
# Каждый запуск:
bash run-local.sh
~~~

Дождитесь «ГОТОВО» и откройте **http://localhost:8080** в браузере Windows.
Терминал должен оставаться открытым. Ctrl+C останавливает сайт и модель.
Повторная установка не скачивает файлы, если их SHA256 совпадает.

Установка скачивает официальные файлы: CPU-движок ~22 МБ и модель 1,12 ГБ.
SHA256 и ревизии зафиксированы в setup-local.sh.
Всё хранится в .local/ и исключено из Git.
Интернет нужен при установке; обработка новостей выполняется локально.

Настройки: 4 CPU-потока, GPU layers = 0, контекст 3072 токена, один слот.
Можно уменьшить нагрузку:

~~~bash
bash run-local.sh --threads 2
~~~

Если порты заняты:

~~~bash
bash run-local.sh --port 8082 --model-port 8092
~~~

Тогда открывайте http://localhost:8082.

## Проверка в интерфейсе

1. Выберите компанию.
2. Нажмите «Оценить новости ленты» или «Оценить AI» у одной карточки.
3. Появятся процент, вердикт, проверенные цитаты (если есть), модель и время.
4. Раскройте «Проверить свою новость», введите заголовок и текст.
5. Смените компанию: старые оценки не подставляются новой компании.

До оценки отображается «Не оценено». Ошибка модели не заменяется нулём
или демобаллом. Обработка последовательная. Кеш в памяти до 256 результатов
учитывает профиль, роль, текст, модель и промпт; очищается при перезапуске.

## Проверки из второго терминала WSL

~~~bash
cd ~/dev/mai/alfa-bank-hackaton/alfa-context
curl http://localhost:8080/api/health
python3 backend/smoke_local.py
(cd backend && python3 -m unittest discover -s tests -v)
~~~

Health должен вернуть ready: true и device: CPU.
Smoke-тест выполняет реальные вызовы: профильная новость, спортивная новость,
программа поддержки без условий; также проверяет повторный запрос из кеша.
Это проверка работоспособности, а не доказательство качества на всех новостях.

## Если ERR_CONNECTION_REFUSED

- Открывайте полный адрес **http://localhost:8080**, а не просто 127.0.0.1:
  без порта браузер обращается к порту 80, где этого сервера нет.
- Сначала запустите bash run-local.sh и дождитесь «ГОТОВО».
- Проверьте curl http://127.0.0.1:8080/api/health внутри WSL.
- Если внутри WSL работает, а в Windows нет, проверьте пересылку localhost
  в настройках WSL и исключения прокси для localhost / 127.0.0.1.
  Сервер слушает только loopback, не локальную сеть.
- Если пишет «Модель ещё не установлена», выполните bash setup-local.sh.
- Если движок завершился: tail -n 50 .local/model.log.
- Старый python -m http.server умеет только отдавать файлы и не запускает модель.
  Для оценки используйте run-local.sh.

## Что означает процент

Это модельная оценка бизнес-релевантности, не вероятность, не достоверность
и не свежесть новости. Порог отбора — 80.
Модель выбирает direct / indirect / none / insufficient_data и балл.
Backend ограничивает балл: indirect <= 79, none <= 20, insufficient_data <= 49.
Высокая оценка принимается только с непустой дословной цитатой новости
и существующим непустым полем компании. Модель выбирает ключ поля, его точное значение подставляет сервер. Неподтверждённая высокая оценка —
ошибка проверки, а не отрицательный вердикт.

Объяснение формируется кодом по классу: маленькая модель не генерирует
произвольные причинно-следственные утверждения.
Проверка цитат подтверждает наличие фрагмента, но не доказывает логическую
правильность связи. Порог требует настройки на размеченной выборке.
При недостатке данных показывается отдельный статус «не отобрана».

Принимаются заголовок до 200 и текст до 2500 символов.
В модель отправляются краткий профиль и по три крупнейшие отрасли
входящих/исходящих платежей. Готовые демоинтерпретации не отправляются.
Даты публикаций пока не учитываются.

## Архитектура и API

- frontend/dist/ — интерфейс, три профиля прежнего прототипа.
- backend/core.py — исходное ядро CSV/SQLite, не менялось.
- backend/server.py — localhost HTTP API, статика, запуск/остановка модели.
- backend/relevance.py — промпт, JSON Schema, проверка, порог, кеш.
- backend/smoke_local.py — небольшой живой тест.
- .local/model.log — журнал движка.

GET /api/health — готовность модели.
POST /api/relevance — JSON:
~~~json
{"company_id":"U_23929","role":"cfo","title":"Заголовок","text":"Текст новости"}
~~~
Роли: cfo / ceo / treasury.
Ответ: score, relevant, status, relation, reason, company_field,
company_quote, news_quote, evidence_verified, threshold, model,
prompt_version, elapsed_seconds, cached.
Ошибки: 400 неверный ввод, 429 модель занята, 503 модель/ответ недоступны.
Статические файлы доступны только из разрешённого списка. Сервер проверяет
Host/Origin, ограничивает тело запроса, не принимает URL для загрузки контента.

## Границы временного решения

Это локальный эксперимент, а не готовое решение всего хакатона.
Qwen2.5 1.5B не входит в разрешённый список LLM из задания.
Для финальной сдачи потребуется разрешённая модель, банковская аналитика,
источники новостей и агентный процесс. Четыре события и их интерпретации
остаются учебными сценариями. Свободный чат не подключён.

Исходные CSV в текущем репозитории отсутствуют; тест локальной модели
работает на экспортированных профилях из frontend/dist/data.js.
