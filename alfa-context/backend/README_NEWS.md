# Парсер новостей: MOEX и ТАСС — 1.0.0

Два источника: MOEX (все новости биржи) и ТАСС (раздел «Экономика и бизнес»).
До 200 новых новостей на источник, опубликованных за последние 48 часов.
Итог — JSON для следующего этапа фильтрации и анализа LLM. LLM и фронт пока
не подключены к парсеру автоматически.

## Запуск через Docker

Все команды выполняются из `alfa-context`, рядом с `compose.yaml`.
Docker Desktop должен быть запущен.

```bash
docker compose build parser
docker compose run --rm parser
```

Без `--sources` запускаются оба источника. По отдельности:

```bash
docker compose run --rm parser --sources moex
docker compose run --rm parser --sources tass
```

Для короткой проверки обоих источников:

```bash
docker compose run --rm parser --limit 5
```

В журнале виден сбор ссылок ТАСС и прогресс обработки статей каждые 10 кандидатов.
После сбора ссылок начинается загрузка полных текстов: на большой порции это
может занимать несколько минут. Файлы появляются после завершения всей порции.

## Обновление с прежней версии и очистка отладочных папок

Скопируйте содержимое `update/` из архива в корень своего репозитория
`Alfa_bank_hack`, рядом с `.gitignore`, с заменой совпадающих файлов.
Полный проект из `Alfa_bank_hack-main/` не используйте для замены своей рабочей ветки.
Устаревшие `alfa-context/FIX_403.md` и `alfa-context/FIX_TASS.md` можно удалить:
все актуальные команды находятся в этом README.

Остановите ранее запущенный парсер. После копирования файлов, из `alfa-context`:

```bash
docker compose build parser
docker compose run --rm --entrypoint python parser -m news_parser.cleanup
docker compose run --rm parser
```

Команда очистки работает с подключённым `data/news` и удаляет только известные
проверочные папки:

- `tass-check`
- `tass-date-check`
- `tass-next-check`
- `tass-scroll-check`
- `tass-full-check`, если она создавалась

Она также удаляет старый `e_disclosure.json`, записи этого источника из общего
JSON, отчёта, состояния и браузерной сессии. Данные и ID MOEX/ТАСС, а также их
браузерные cookies сохраняются. Остальные каталоги не удаляются. Повторная
очистка допустима. Прерванная транзакция прежней версии сначала восстанавливается
в формате двух источников.

Обычный запуск больше не создаёт ни отладочных подпапок, ни файл удалённого
источника. Результаты всегда в одной папке `alfa-context/data/news/`.

## Результат

| Файл | Содержимое |
| --- | --- |
| `moex.json` | Новые новости MOEX |
| `tass.json` | Новые новости экономики ТАСС |
| `news.json` | Общий массив двух источников, максимум 400 записей |
| `run_report.json` | Статусы, окно времени, счётчики, ошибки и предупреждения |
| `state.json` | Только ID и даты публикаций для дедупликации |

Браузерная сессия хранится в `.browser-state.json`. Не отправляйте её в Git
или ML-компонент. Данные в `data/` уже исключены через `.gitignore`.

Три новостных файла — UTF-8 JSON-массивы с одинаковой схемой:

```json
{
  "id": "tass:0123456789abcdef01234567",
  "source": "tass",
  "url": "https://tass.ru/ekonomika/123456",
  "title": "Заголовок",
  "text": "Полный текст статьи с сохранением абзацев.",
  "published_at": "2026-10-23T06:00:00+00:00",
  "collected_at": "2026-10-23T06:10:00+00:00",
  "categories": ["Экономика и бизнес"],
  "issuer": null,
  "language": "ru"
}
```

Это пример структуры, не реальная новость. Схема: `news_parser/news.schema.json`.
Даты выдаются в UTC. Дата публикации отделена от даты обновления и даты события
в тексте. `collected_at` совпадает с началом запуска и `window_end` в отчёте.

## Только новые новости

Каждый запуск заменяет предыдущие новостные JSON новой порцией, а не дописывает
архив. ID из `state.json` повторно не выдаются; записи состояния старше 48 часов
удаляются. Поэтому повторный запуск может дать меньше 200 записей или пустой массив.
Это нормальный результат, если доступные новости уже были выгружены.

Ошибочные, недатированные и слишком короткие записи не помечаются обработанными:
следующий запуск может попытаться загрузить их снова. Для LLM читайте порцию после
завершения процесса и до следующего запуска. Обновление уже выгруженной статьи
не приводит к её повторному экспорту. Между источниками события не объединяются —
это задача следующего этапа ML.

## Проверка JSON и автоматические тесты

```bash
docker compose --profile test run --build --rm parser-test
```

В UCRT64/MSYS2 проверяйте готовую порцию так:

```bash
MSYS2_ARG_CONV_EXCL='*' docker compose run --rm --entrypoint python parser -m news_parser.check /data
```

Префикс отключает преобразование `/data` в Windows-путь. Для обычного запуска
и очистки он не нужен: путь берётся из конфигурации контейнера, а не из аргумента
оболочки. В PowerShell и обычном Linux терминале префикс можно опустить.
Проверяются схема записей, окно 48 часов, ID, лимиты и согласованность трёх
новостных файлов с отчётом.

Тесты не требуют доступа к сайтам: HTTP и браузерные ответы перехватываются.
Отдельно проверяются реальные фрагменты присланных HTML ТАСС, извлечение дат,
бесконечная прокрутка и обновление старого состояния без потери ID двух источников.

## Способы загрузки

MOEX: сначала ISS API со страницами `sitenews` и полными текстами `content`,
затем RSS, HTTP HTML и Chromium как резервные способы.

ТАСС: RSS экономических новостей, HTTP HTML и Chromium. RSS-анонс не считается
полным текстом. Дата берётся из JSON-LD, включая очереди Next.js `__next_s` и
`__next_f`, метаданных текущей статьи или RSS. JavaScript из HTML для разбора
метаданных не исполняется. Запасной разбор видимого времени учитывает Москву,
переход суток, год и отличие публикации от обновления.

Для бесконечной прокрутки Chromium выводит в область видимости индикатор
`InfiniteLoading` после карточек; переход к самому низу секции `5000vh` не
используется. Парсер ждёт новые ID, поддерживает отдельный прокручиваемый
контейнер и замену карточек. Ожидание ограничено меньшим из `--timeout` и
`--browser-timeout`, с одной повторной попыткой. `--max-pages` ограничивает
количество прочитанных порций. Если доступных ссылок недостаточно, отчёт честно
показывает неподтверждённое покрытие 48 часов; число 200 — верхний предел.

## Параметры

```bash
docker compose run --rm parser --sources moex tass --hours 48 --limit 200 --max-pages 20
```

`--hours`: 1–48; `--limit`: 1–200 на источник; `--max-pages`: максимум порций списка.
`--timeout`: HTTP и ожидание подгрузки, по умолчанию 20 секунд;
`--browser-timeout`: ожидание браузера, по умолчанию 60 секунд;
`--delay`: интервал запросов к одному хосту, по умолчанию 0,5 секунды;
`--retries`: дополнительные HTTP-попытки; `--no-browser`: отключить Chromium.
Источники обрабатываются параллельно, статьи внутри каждого источника — последовательно.

Код завершения: `0` — все запрошенные источники без замечаний, `2` — частичная
выгрузка/предупреждения, `1` — все запрошенные источники недоступны или общая ошибка.
При частичном результате готовые новости всё равно сохраняются.

## Если ТАСС просит проверку посетителя

Сначала попробуйте обычный запуск: сохранённая сессия переиспользуется автоматически.
Если сайт требует ручной проверки, используйте дополнительный профиль:

```bash
docker compose -f compose.session.yaml build parser-session
docker compose -f compose.session.yaml run --rm --service-ports parser-session
```

Откройте `http://localhost:6080/vnc.html?autoconnect=true&resize=scale`, дождитесь
ленты ТАСС, при необходимости пройдите CAPTCHA вручную и нажмите Enter в терминале.
Затем повторите обычный запуск парсера из той же сети. Автоматического решения
CAPTCHA в проекте нет.

## Без Docker

Из `alfa-context/backend`, в виртуальном окружении Python 3.12+:

```bash
python -m pip install -r requirements-parser.txt
python -m playwright install chromium
python -m news_parser --output ../data/news
```

На Linux при отсутствии системных библиотек браузера используйте
`python -m playwright install --with-deps chromium`.

Для очистки и проверки:

```bash
python -m news_parser.cleanup ../data/news
python -m news_parser.check ../data/news
```

Для тестов установите `requirements-test.txt` и запустите `python -m pytest -q`.
