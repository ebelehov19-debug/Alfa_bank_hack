# Альфа Контекст — ядро варианта 2

Первая реализованная часть системы: импорт исходных CSV, контроль качества,
профиль компании, связи через платежи, группы и общих физических лиц.
Это НЕ готовая новостная система: интерфейс, сбор новостей, банковский RAG и
агентный цикл ещё предстоит реализовать после настройки доступа к моделям.

## Запуск

Python 3.12+, только стандартная библиотека. Зависимостей pip нет.
Исходные CSV положите в отдельную папку `data`.

```bash
python core.py import data
python core.py quality
python core.py profile U_67
python -m unittest discover -s tests -v
```

SQLite используется как автономный проверяемый этап подготовки данных.
Целевой сервис: React/TypeScript, FastAPI, PostgreSQL, отдельный процесс
сбора/обработки материалов, Docker Compose. Миграция хранилища входит
в следующий этап; этот архив не заменяет итоговый Docker-прототип.

## Реальные особенности данных

- 85 525 строк профилей, 85 514 уникальных компаний.
- У U_428697 двенадцать противоречивых профилей. Конфликтующие поля заменяются
  на null, все варианты сохраняются в company_rows и conflicts.
- 1 380 585 строк платежей; у 582 165 строк нет профиля плательщика,
  у 409 024 — профиля получателя. Эти категории могут пересекаться.
- 27 406 платежных строк связывают компанию с самой собой; исключены из
  анализа внешних контрагентов.
- 17 повторов пары отправитель/получатель сверх первой строки сохраняются:
  нет основания считать их ошибочными дублями. Суммы агрегируются.
- 12 514 строк связей с физическими лицами. Общий человек не доказывает
  владение, контроль или принадлежность компаний к одной группе.

Все суммы обрабатываются Decimal. Валюта, единицы измерения выручки,
период платежей и назначения переводов требуют подтверждения организаторов.
Без дат нельзя рассчитывать тренды, просрочки или динамику отношений.
Покрытие отраслевыми данными считается по объёму всех внешних платежей;
неизвестные контрагенты не исчезают из знаменателя.

## Следующий этап системы

1. Подключить утвержденные LLM через адаптер провайдера, точные ID моделей
   взять из его документации. Ключи только в серверных переменных окружения.
2. Реализовать разрешённые источники новостей: RSS/HTML адаптеры, таймауты,
   ограничение размера, повторные попытки, защита от SSRF и дубликатов.
3. Загрузить аналитические документы банка: текст, дата, страницы, чанки,
   поиск с проверяемыми ссылками. Не подменять отсутствие материалов
   сгенерированной «позицией банка».
4. Ранжировать события по прямым признакам компании и отраслевым долям
   контрагентов. Роль пользователя — явный выбор, из CSV она неизвестна.
5. Собственный агент: план, инструменты, структурированный черновик,
   проверка оснований и повторный поиск с ограничением числа итераций.
6. UI: лента, профиль, связи, карточка события, источники, вопросы и
   журнал действий. Раздельные блоки фактов, позиции банка и выводов AI.
7. Авторизация и проверка доступа к компании до каждого инструмента;
   минимизация передаваемых модели данных, журнал без секретов,
   общий учёт бюджета и токенов, ограничения действий агента.
8. Сквозные тесты, синтетический демонабор, Docker Compose, зафиксированные
   зависимости, GitHub, THIRD_PARTY_NOTICES и сценарий защиты.

Для завершения нужны API base_url, разрешённые идентификаторы моделей,
документация провайдера, материалы аналитики банка и срок сдачи.
Реальные CSV в архив не включены; используются предоставленные отдельно файлы.
